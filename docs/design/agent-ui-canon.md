# Agent UI Canon

This document is the product-UI canon for Codex and other agents working on the MES Demo Advisor.

## Product Position

- This is a consultant-facing MES workflow tool.
- The application should feel credible, operational, calm, and review-first.
- The product is not an analytics showcase, consumer app, or executive KPI dashboard.

## Preferred Visual Language

- Build around a strong workspace shell, clear section hierarchy, and restrained accent usage.
- Default to neutral surfaces with one brand-led accent family.
- Use emphasis to guide work, not to decorate every region.
- Prefer layout structure, type scale, spacing rhythm, and state clarity over ornamental chrome.

## Surface Archetypes

### Product workspace

- Primary patterns: table-detail, queue-detail, editor-detail, split workspace, progress rail
- Main goal: help consultants review, decide, edit, approve, and export
- Avoid: stacked card grids, hero banners, decorative metrics, too many chips

### Wizard or form

- Group fields by task, not by arbitrary boxes
- Keep the next step obvious
- Use side guidance sparingly and only when it reduces uncertainty
- Make validation and processing states explicit

### Settings or admin

- Use plain labels, explicit descriptions, and low visual noise
- Dangerous or advanced actions should stand out through wording and spacing, not spectacle

### Empty or onboarding

- Show what this area is for
- Explain the first useful action
- Keep reassurance and orientation short
- Avoid generic illustration-heavy filler

## Density and Spacing Guidance

- Default density: comfortable-compact
- Data-heavy surfaces should feel efficient, not airy
- Use generous spacing between major regions, tighter spacing within a region
- Avoid deep nesting of panels with repeated borders, glows, or shadows
- Use cards only when a card is the actual interaction unit

## Copy Tone

- Prefer utility copy over marketing copy on product surfaces
- Headings should describe the area or action, not sell the product
- Supporting copy should clarify scope, status, consequences, or next steps
- Avoid vague value lines like "unlock insights", "transform your workflow", or "seamless experience"

## Good vs Bad

### Good

- "Requirements review"
- "12 rows still need consultant review before script generation."
- "Upload the source workbook to create a reviewable Phase 1 draft."
- "Generate script" is disabled until review blockers are resolved.

### Bad

- "AI-powered excellence dashboard"
- "Supercharge your manufacturing journey"
- Large decorative KPI tiles that do not affect the next action
- A Phase 2 CTA that visually reads as the only way to finish Phase 1

## Layout Rules for This Product

- Review screens should anchor around the work artifact first, with context and actions close to that artifact.
- Tables should optimize scanning and comparison, with row detail shown in an inspector or adjacent panel.
- Progress rails are appropriate for setup, upload, processing, and staged review flows.
- Export readiness, traceability, and review state should be visible before export actions.

## Acceptance Checklist

- Is the screen clearly a product workspace instead of a marketing page?
- Can a consultant tell what to do next in under five seconds?
- Is the dominant action obvious without overpowering supporting actions?
- Does the copy explain the work instead of describing the design?
- Are Phase 1 and Phase 2 scoped honestly?
- Are the layout pattern and visual emphasis appropriate for the screen type?
