## Product UI Direction

The app is a calm, utility-first consultant workspace. It should feel like a workbench for repeated review and editing, not a landing page.

Default UI priorities:

1. task clarity
2. route and state clarity
3. readable tables and review queues
4. strong empty and blocked states
5. mobile usability
6. visual restraint

## Theme

The product theme uses a `data-theme` attribute and the storage key:

```text
cm-mes-advisor:theme:v2
```

The default theme is light.

The docs site uses Fumadocs theme handling for the docs layout with the storage key:

```text
cm-mes-advisor:docs-theme:v2
```

Fumadocs updates both the `class` and `data-theme` attributes. Keep those attributes synchronized so the docs UI and product theme tokens do not fight each other.

## UI Rules From The Repo

Follow `AGENTS.md` and `src/AGENTS.md` for frontend work.

Important rules:

- classify the surface before editing
- state the user job and dominant action
- avoid generic card mosaics for product workspaces
- avoid decorative gradients on routine product surfaces
- keep copy operational and scannable
- do not add a second design system
- verify desktop and mobile before calling UI work done

## Surface Types

Most app screens are `product workspace` surfaces.

The docs site is an `empty/onboarding` surface because the user job is orientation and navigation.

Settings/admin, wizard/form, and landing/marketing patterns should not be imported into the Phase 1 workbench unless the task truly requires that surface type.

## Empty, Blocked, And Error States

Important states to check when editing UI:

- no projects yet
- no parsed workbook rows
- generation unavailable
- no generated drafts
- no approved rows
- no script steps
- export not ready
- mobile overflow
- long requirement text
- storage failures

The routed workflow should guide teammates to the next useful step instead of leaving them on a broken or misleading screen.

## Browser Verification

For meaningful UI changes, verify:

- desktop route rendering
- mobile route rendering
- no horizontal overflow
- current task is visible before navigation on mobile
- theme still works
- no conflicting next-action copy
- the requested outcome is visible in the browser, not only in code

The Playwright smoke test is in `tests/e2e/phase1-smoke.spec.ts`.
